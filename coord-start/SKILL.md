## 📁 创建的目录结构

### service-info.json 配置策略

```
项目根目录/
├── service-info.json          # ⭐ 项目级配置（可选）
│   所有需求共享同一份服务配置（URL、API规则等）
│
├── REQ-001/
│   ├── service-info.json      # 可选：需求级配置（独立）
│   │   如果存在，则优先使用此配置
│   ├── README.md
│   ├── feedback.md
│   ├── closed.md
│   ├── backend/
│   ├── frontend/
│   └── testing/
│
└── REQ-002/
    └── ...
```

### 配置文件优先级

1. **需求目录有 `service-info.json`** → 使用需求级配置
2. **需求目录没有，但项目根目录有** → 使用项目级配置
3. **都没有** → 创建新的项目级配置

### 选择配置策略的场景

| 场景 | 推荐配置 |
|------|---------|
| 多个需求共用同一套后端/前端服务 | 项目级配置 |
| 不同需求有不同服务端口或 API 版本 | 需求级配置 |
| 需要对单个需求进行特殊配置 | 需求级配置 |
