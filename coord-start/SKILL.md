# /coord-start - 初始化联调测试项目

## 🎯 交互式初始化流程

运行 `/coord-start` 后，按照提示选择或输入：

### 📁 步骤 1：询问工作目录（始终进行）

```

│  📁 工作目录:                                    │
│                                                 │

│                                                 │
│  小字: 工作目录指的是所有测试工作的工作目录，     │
│       会在此生成测试产物（报告、日志等）           │
```

## 📁 目录结构说明

### 工作目录 vs 项目目录

| 概念 | 说明 |
|------|------|
| **工作目录** | 测试工作所在目录，存放 service-info.json、需求子目录、测试报告等产物 |
| **项目目录** | 被测试的实际项目代码目录（如 lumina 前端项目），与测试工作分开 |

### 工作目录结构

```
{工作目录}/
├── service-info.json          # 服务配置（所有需求共用，或需求级独立）
├── REQ-001/                   # 需求目录
│   ├── README.md             # 需求协调手册
│   ├── feedback.md           # 问题追踪
│   ├── closed.md             # 已关闭问题
│   ├── backend/             # 后端相关文件
│   ├── frontend/             # 前端相关文件
│   └── testing/             # 测试文件
└── REQ-002/
    └── ...
```

### 配置文件优先级

1. **需求目录有 `service-info.json`** → 使用需求级配置
2. **需求目录没有，但工作目录有** → 使用工作目录级配置
3. **都没有** → 创建新的配置
